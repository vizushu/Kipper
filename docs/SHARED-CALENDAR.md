# Shared calendar: staged, not activated

The owner confirmed Airbnb and direct bookings will coexist. This adapter improves visibility; **iCal is not an atomic cross-platform reservation lock**. Airbnb says its calendar refreshes imported feeds every three hours, manual refresh is limited, and how quickly an exported change appears elsewhere depends on the receiving site. Some imported manually blocked/preparation dates may not block Airbnb. Source: https://www.airbnb.com/help/article/99 (checked 2026-10-31).

## Implemented code
- SQLite source-scoped snapshots for the single physical Casa Pacifica inventory. Three-/five-bedroom configuration IDs resolve to the same inventory; existing expansion/capacity gates remain.
- Strict all-day `VALUE=DATE` events, checkout-exclusive `DTEND`, including DST boundaries without UTC date shifts. Missing end means one day. Timed/TZID/recurring/unsupported data fails the entire import instead of guessing occupancy.
- Stable hashed UID provenance, identical-event deduplication, moved-event replacement, explicit cancellation and removed-event reconciliation. No raw UID, SUMMARY, DESCRIPTION, URL or guest details are persisted.
- Full parse before one transactional replace. Manual/other-source blocks survive. Fetch/parse failure preserves last-good blocks, marks unhealthy and blocks new holds/confirmation. Empty snapshots need explicit admin confirmation; scheduled work cannot silently clear all blocks.
- Two-minute source lease prevents duplicate/out-of-order sync results. Fifteen-minute last-success freshness is a local safety threshold, NOT a promise of upstream freshness. Required-but-missing, stale, failed or conflicting sources block quote/availability and SQLite hold/payment-confirmation transactions.
- Imported overlaps with existing confirmed/active-held stays create durable conflict records; no guest cancellation, payment refund or booking overwrite occurs. Admin may acknowledge only after actual overlaps are gone. Source status exposes counts and review timestamps, not guests.
- Outbound capability-protected busy calendar includes only live-paid confirmed bookings, live unexpired holds and manual blocks. It excludes imported source blocks and historical test bookings. Generic `Unavailable` summaries, opaque HMAC event IDs, no guest/contact/address/pricing/payment metadata. Removing/cancelling direct inventory removes it from the next snapshot. Short holds should NOT be relied on to reach Airbnb before they expire.
- Own exported UID suffix is ignored on import. If another platform rewrites those IDs, a mirror cannot be distinguished safely from a real conflicting booking; conflict review remains necessary. Never import the direct export as the Airbnb source.
- Strict HTTPS `www.airbnb.com/calendar/ical/{id}.ics` only; normal private query parameters supported but never logged. All DNS results must be public; the selected result is pinned for TLS connection. Redirects, compression, non-calendar/HTML responses, oversized (>1MiB) and slow (>10s total) feeds reject. No arbitrary URL fetch endpoint.
- Supabase remote-calendar persistence is explicitly unsupported and fails closed; do not activate these flags on that adapter without a separately tested implementation.

## Routes / operational actions
- `GET /api/admin/calendar`: authenticated safe source status/counts and lag warning.
- `POST /api/admin/calendar`: existing admin + mutation-origin guard, action `sync` or `review-conflict`. `confirmEmptySnapshot:true` is an explicit operator decision for an empty result, never the scheduler default. Review actual upstream calendar before approving it.
- `GET/POST /api/calendar/sync`: dedicated Bearer worker/operator credential, explicit calendar-only approval and sync flag; safe status or bounded sync/review actions. Wrong/disabled credentials return404 before database/network access. POST is persistently limited to12 operations/15minutes; use this scoped route for an approved scheduler while booking preview stays closed. Never put the worker credential in a URL. Operator-only empty-snapshot confirmation/review must not be added to automatic scheduler payloads.
- Existing authenticated maintenance step optionally syncs once before bounded hold/outbox work. No scheduler/service was provisioned. The normal admin/maintenance routes remain preview-disabled. A separate calendar-only approval and scoped worker credential can enable private calendar operations while guest booking/payment guards remain closed.
- Private outbound route is `/api/calendar/direct.ics` with its capability supplied as a `key` query parameter. **Do not publish the completed URL or token in source, issues, screenshots, Notion or logs.** Do not add it to navigation. It returns404 unless separately approved, enabled and capability-authorized; valid responses are no-store/noindex with calendar content type.

## Separate owner approval / activation gates
No feed has been fetched, stored, generated, registered with Airbnb or enabled by this code checkpoint. These are distinct actions requiring approval:
1. Store the owner-provided inbound URL in server-only `AIRBNB_ICAL_URL`; never `NEXT_PUBLIC_…` or repository configuration.
2. Generate a cryptographically random outbound capability (at least32bytes, base64url), store server-only `CALENDAR_EXPORT_TOKEN`, and privately supply the resulting URL to Airbnb. Rotation revokes the old URL and changes opaque event IDs; update the receiving calendar intentionally. Protect provider access logs because query capabilities may otherwise be recorded.
3. Separately approve `CALENDAR_OPERATIONS_APPROVED=true`, `CALENDAR_SYNC_ENABLED=true`, `CALENDAR_SYNC_REQUIRED=true` and eventually `CALENDAR_EXPORT_ENABLED=true` after operational verification. This does not change `SITE_PREVIEW_MODE` or enable booking/payment. Generate/store a distinct high-entropy server-only `CALENDAR_WORKER_SECRET` only after owner approval; it authorizes calendar operations, not general admin or checkout. Enabling sync/required/export **also keeps shared-channel live instant payment blocked**, even if legacy exclusive-direct flags are mistakenly present.
4. Verify actual URL response compatibility in a private dry run, review initial events/counts against Airbnb, execute synthetic/staged inbound/outbound round trip, measure delays, verify deletion/cancellation/empty handling and receiver treatment of manual blocks. Never test with an actual guest booking or charge.
5. Configure and verify authenticated scheduler execution/freshness monitoring, durable disk/backup, conflict-review coverage and capability rotation. No paid scheduler or new admin credentials are authorized by code publication.
6. Choose a safe shared-channel launch workflow. Request-only/manual cross-check can be a separate build; this checkpoint does not implement or enable it. Alternatively use a separately verified authoritative channel-manager integration. Do not claim shared iCal alone enables reliable simultaneous instant booking. Do not assert the owner delisted Airbnb or chose exclusive-direct inventory.

All current guest booking/payment/messaging preview guards remain closed. The new independent calendar approval is default-off and has not been configured. Synthetic tests and source review are not a live provider integration certification.
